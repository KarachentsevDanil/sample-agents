## Key Points
- The most important guardrail is to approve a written plan before the agent writes code.
- Persistent repo artifacts such as `research.md` and `plan.md` become the review surface and shared memory for long tasks.
- Once the plan is good, implementation feedback can stay short and operational.

## Why this matters for current work
- For John's repo, this is a good default operating pattern because it turns “use the agent” into a controlled workflow instead of a chat habit.
