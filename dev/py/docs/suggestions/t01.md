# Task t01: Remove all captured cards and threads

## Failure Summary

**Instruction**: "Let's start over. Remove all captured cards and threads. Do not touch anything else"

**Expected**: Delete all 5 card files in `02_distill/cards/` AND all 2 thread files in `02_distill/threads/` (excluding template files starting with `_`). Return OUTCOME_OK.

**Actual**: Agent deleted all 5 card files but left both thread files intact. The agent explicitly rationalized skipping thread deletion in its done() message: "No threads were updated because there are no remaining card links after deleting the cards; nothing else was modified." Score: 0.0.

## Root Cause Analysis

### Context Builder Phase

The context agent discovered and read the relevant authority files:
- `AGENTS.MD` (root) -- describes repo structure including `02_distill/cards/` and `02_distill/threads/`
- `02_distill/AGENTS.md` -- explicitly describes cards and threads as separate entities within the distill folder
- `02_distill/cards/_card-template.md` and `02_distill/threads/_thread-template.md`

**Finding**: Context discovery was adequate. The context agent correctly identified both `cards/` and `threads/` as relevant areas. No missing context here.

### Planner Phase

The planner received 3,928 input tokens and produced 452 output tokens. The plan output itself was not logged (only the usage metrics were stored in `api_calls.jsonl`), so the exact plan text is not directly observable.

However, based on `result.json`:
- `plan_steps_count`: 5
- `plan_complexity`: "medium"

And based on what the ReAct loop actually did (15 steps total):
1. Steps 1-2: Listed `02_distill/cards/` and `02_distill/threads/` (both directories explored)
2. Steps 3-9: Read all 5 card files and both 2 thread files
3. Steps 10-14: Deleted only the 5 card files
4. Step 15: Called done() without deleting threads

**Finding**: The ReAct loop DID browse and read both thread files (steps 8-9), which means either (a) the plan included reading threads but not deleting them, or (b) the plan included deleting threads but the model chose to interpret the task differently during execution.

The critical signal is the done() message: the agent rationalized that threads don't need deletion because "there are no remaining card links after deleting the cards." This reveals the model reinterpreted the explicit instruction "Remove all captured cards **and threads**" as "remove cards; threads are just indexes of cards so they'll be orphaned and that's fine."

### ReAct Phase

Step-by-step trace:

| Step | Tool | Target | Purpose |
|------|------|--------|---------|
| 1 | browse(ls) | `02_distill/cards/` | Enumerate card files |
| 2 | browse(ls) | `02_distill/threads/` | Enumerate thread files |
| 3-7 | read_file | All 5 card files | Read each card (unnecessary for deletion task) |
| 8-9 | read_file | Both thread files | Read each thread (unnecessary for deletion task) |
| 10-14 | delete_file | All 5 card files | Delete cards |
| 15 | done() | -- | Report completion, **omitting thread deletions** |

Key observations:
1. **The agent read files it didn't need to read** -- 7 unnecessary read_file calls (steps 3-9) for a deletion task where listing was sufficient.
2. **The agent knew the threads existed** -- it browsed and read both thread files, so this is not a discovery failure.
3. **The agent actively decided NOT to delete threads** -- the done() message shows deliberate reasoning: "No threads were updated because there are no remaining card links."
4. **The thread files are NOT listed in the done() refs** -- confirming the agent considered them read-only context, not deletion targets.

### Primary Root Cause

The model semantically reinterpreted "remove threads" as "threads are indexes of cards, so removing cards implicitly handles threads" instead of treating the instruction literally as "delete the thread files."

## Suggestions (generalizable, not task-specific)

### S1: Add a plan-to-execution verification step for destructive operations

- **What**: After the plan is generated, inject a lightweight verification prompt that checks: "The plan says to delete files X, Y, Z. The task says to remove A and B. Are all items from the task covered in the plan?" Run this as a separate structured-output call before ReAct begins.
- **Where**: `agent_pipeline_openai/stages/planning.py` -- add a `_verify_plan_coverage()` method after plan generation
- **Why**: The planner may produce a plan that covers one category of targets (cards) but omits another (threads) because the model infers a semantic relationship. A mechanical coverage check prevents this class of error.
- **Scope**: pipeline_stage
- **Confidence**: MEDIUM

### S2: Log the full plan output in api_calls.jsonl

- **What**: Store the serialized `TaskPlan` object (task_interpretation, steps, relevant_rules) in the planning api_call log entry, not just the usage stats.
- **Where**: `agent_pipeline_openai/stages/planning.py`, line ~40-50 in the `logger.append_api_call()` call
- **Why**: Without the plan text, post-hoc debugging requires inference from the ReAct trace. Logging the plan enables direct diagnosis of planner vs. executor failures and supports automated plan quality checks.
- **Scope**: pipeline_stage
- **Confidence**: HIGH

### S3: Add a system prompt rule against semantic reinterpretation of explicit nouns

- **What**: Add to the system prompt: "When the task explicitly names categories of items to act on (e.g., 'cards and threads'), treat each named category as a separate, literal target. Do not collapse categories by inferring one is a derivative of another."
- **Where**: `agent_pipeline_openai/prompt_resources/prompts/system/v13.yaml` under the SCOPE section
- **Why**: The model's failure here was reinterpreting "threads" as "just indexes of cards." This is a general failure mode where models use domain knowledge to override explicit instructions. A rule against collapsing explicit nouns prevents this across many tasks.
- **Scope**: system_prompt
- **Confidence**: HIGH

### S4: Reduce unnecessary read_file calls for destructive-only tasks

- **What**: In the planning prompt, add guidance: "For deletion tasks, listing directory contents is sufficient to identify targets. Do not plan read_file steps for files that will be deleted unless content inspection is needed to decide *whether* to delete."
- **Where**: `agent_pipeline_openai/prompt_resources/prompts/planning/v2.yaml`
- **Why**: This run wasted 7 steps (out of 15) reading file contents that were immediately deleted. Reducing unnecessary reads leaves more budget for the actual required operations and reduces the chance of the model being distracted by file contents (which may have contributed to the "threads are just card indexes" rationalization).
- **Scope**: system_prompt
- **Confidence**: MEDIUM

### S5: Pre-load past mistakes with higher visibility

- **What**: The errors.jsonl for t01 contains 12 entries documenting extensive trial history. Entries 9 and 12 directly describe this exact failure mode (missing thread deletes). Ensure the most relevant past mistake (the one matching the current failure pattern) is surfaced first in the `PAST MISTAKES` section, with specific file paths mentioned.
- **Where**: `agent_pipeline_openai/prompt_resources/prompts.py`, lines 42-53 in `build_initial_user_message()`
- **Why**: The past mistakes section currently shows up to 3 mistakes with truncated detail. For t01, entries about "missing file delete threads" should have been the highest-signal mistake. If the selection favors recency over relevance, the wrong mistakes get surfaced.
- **Scope**: preloading
- **Confidence**: MEDIUM

## Tool Recommendations

- **No new tools needed.** The agent had browse, read_file, delete_file, and done -- all sufficient for this task.
- **Reduce tool misuse**: The agent made 7 unnecessary read_file calls. The planning prompt should discourage reading files that are about to be deleted. This is a prompt/planning issue, not a tool gap.

## Rule Recommendations

- Add a rule: "When the task says 'remove X and Y,' treat X and Y as independent targets. Do not infer that handling X makes Y unnecessary."
- Add a rule: "For bulk deletion tasks, confirm all target categories are covered before calling done()."
- Do NOT add a t01-specific rule like "threads must be deleted with cards." The rule should be about literal interpretation of conjunctive instructions.

## Pipeline / Pre-loading Recommendations

- **Log full plan**: The plan output is currently discarded after being passed to the ReAct loop. Logging it enables automated plan-quality analysis across runs.
- **Add a done()-gate checklist**: Before the agent calls done(), the pipeline could inject a brief "did you complete all parts of the instruction?" prompt. This would catch partial completions where the agent rationalized skipping work.
- **Past-mistake selection**: The current `[:3]` slice of past_mistakes may miss the most relevant error. Consider sorting by similarity to the current failure pattern before slicing, or including errors that mention specific missing operations.
